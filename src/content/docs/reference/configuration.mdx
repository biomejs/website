This reference covers all supported options in `biome.json`/`biome.jsonc`. For a step-by-step introduction, see the [Configure Biome](/guides/configure-biome/) guide.

To get started, scaffold a minimal `biome.jsonc` file using the `biome init` CLI command:

```sh
biome init --jsonc
```

:::note
In option paths, `<ITEM>` represents an array item, while square-bracket placeholders such as `[group]`, `[rule]`, and `[action]` represent a supported name.
:::

## `$schema`

**Type:** `string`

Specifies the [JSON Schema](https://json-schema.org/) used to validate the configuration and provide editor features such as completion and inline documentation.

If `@biomejs/biome` is installed locally, reference the schema included in the npm package, which always matches the installed Biome version:

```json title="biome.json"
{
  "$schema": "./node_modules/@biomejs/biome/configuration_schema.json"
}
```

If your editor cannot resolve the local file, use the schema published on the Biome website:

```json title="biome.json"
{
  "$schema": "https://biomejs.dev/schemas/latest/schema.json"
}
```

:::tip
Replace `latest` with your installed Biome version, for example `2.5.10`, to get the most accurate validation and documentation.

Biome will also warn you when your `$schema` URL version doesn't match the package version.
:::

## `extends`

**Type:** `"//" | string[]`

Extends the current configuration with settings from one or more other Biome configurations.

In a nested configuration, use `"//"` to extend the root configuration without specifying a relative path. This works at any nesting depth:

```json title="packages/frontend/biome.json"
{
  "extends": "//"
}
```

To extend configurations using relative paths or installed package specifiers, use an array:

```json title="biome.json"
{
  "extends": ["./common.json", "@org/shared-configs/biome"]
}
```

Biome merges configurations from left to right. For options that accept a single value, later configurations take precedence. For options that accept a list, Biome combines their entries. The current file is applied last.

See the [Use Biome in big projects](/guides/big-projects#monorepo) guide for monorepo setup and shared configuration examples.

## `root`

**Type:** `boolean`<br />
**Default:** `true`

Marks whether this file is the root configuration for a Biome project. The root configuration establishes the project's base settings, while `"root": false` tells Biome that a configuration found inside the project is nested rather than a second project root.

Biome implicitly treats `root` as `false` when a nested configuration uses `"extends": "//"`, while all other nested configurations must explicitly set `"root": false` to avoid an error.

## `plugins`

**Type:** `(string | { path: string, includes?: string[] })[]`

A list of [GritQL plugins](/linter/plugins/) to load. Each entry is either a plugin path or an object containing a path and optional file filters:

```json title="biome.json"
{
  "plugins": [
    "./general-plugin.grit",
    {
      "path": "./react-plugin.grit",
      "includes": ["**/src/components/**", "!**/src/components/generated/**"]
    }
  ]
}
```

### `plugins.<ITEM>.path`

**Type:** `string`

Path to the plugin's `.grit` file or a directory containing `biome-manifest.jsonc`.

### `plugins.<ITEM>.includes`

**Type:** `string[]`

A list of [glob patterns](#glob-syntax-reference) selecting the files on which the plugin runs.

If omitted, the plugin runs on every file eligible for linting. An empty list (`[]`) selects no files.

## `files`

**Type:** `{ includes?: string[], ignoreUnknown?: boolean, maxSize?: integer, experimentalScannerIgnores?: string[] }`

Configures which files Biome can discover and process.

### `files.includes`

**Type:** `string[]`

A list of [glob patterns](#glob-syntax-reference) selecting which files and directories Biome can process.

If omitted, this option does not further restrict the supported files Biome can process. An empty list (`[]`) selects no files.

For example, this includes all JavaScript files below `src`:

```json title="biome.json"
{
  "files": {
    "includes": ["src/**/*.js"]
  }
}
```

:::note
Biome ignores files under `node_modules/` even if they match a `files.includes` pattern.
:::

#### Scanner behavior

Biome's [scanner](/internals/architecture/#scanner) is responsible for discovering nested configuration and ignore files. When enabled rules use the [`project` or `types` domains](/linter/domains/), it also indexes source files and project dependencies.

The scanner respects `files.includes` and, when enabled, VCS ignore files. However, it may still discover required metadata or index excluded source files needed for analysis. To ensure that a path is never indexed, use a [force-ignore pattern](#glob-syntax-reference):

```json title="biome.json"
{
  "files": {
    "includes": ["**", "!!**/dist"]
  }
}
```

Force-ignore build output and nested projects that Biome should not inspect. Prefer a regular exclusion for generated source files that provide types or other project information.

### `files.ignoreUnknown`

**Type:** `boolean`<br />
**Default:** `false`

Controls whether Biome suppresses diagnostics for unrecognized file types.

### `files.maxSize`

**Type:** `integer`<br />
**Default:** `1048576`

Sets the maximum source code file size in bytes. Biome will skip files above this limit for performance reasons and emit a warning diagnostic.

### `files.experimentalScannerIgnores`

**Type:** `string[]`

:::caution[Deprecated]
This option is deprecated and may be removed in a future release. Use [force-ignore patterns](#glob-syntax-reference) in `files.includes` instead, or run `biome migrate` to update the configuration.
:::

A list of file or directory names that the scanner ignores unconditionally while crawling. Each value matches a complete path component, not a glob.

Ignored files are not added to the module graph and therefore types won't be inferred from them.

## `vcs`

**Type:** `{ enabled?: boolean, clientKind?: "git", useIgnoreFile?: boolean, root?: string, defaultBranch?: string }`

Configures how Biome integrates with a version control system (VCS).

### `vcs.enabled`

**Type:** `boolean`<br />
**Default:** `false`

Enables or disables version-control integration. Enabling it requires `vcs.clientKind` to be set.

### `vcs.clientKind`

**Type:** `"git"`

Selects the version-control client. Currently, only `"git"` is supported.

### `vcs.useIgnoreFile`

**Type:** `boolean`<br />
**Default:** `false`

Controls whether Biome applies patterns from `.gitignore`, Git's local `.git/info/exclude`, and supported `.ignore` files, including nested ignore files.

Patterns in the root ignore file are resolved from `vcs.root` while patterns in nested ignore files are resolved from the directory containing that file.

### `vcs.root`

**Type:** `string`

Sets the directory where Biome looks for version-control files. A relative value is resolved from the directory containing the current configuration file, while an absolute path is used directly.

Set this option when the Biome configuration is not located at the repository root:

```json title="frontend/biome.json"
{
  "vcs": {
    "enabled": true,
    "clientKind": "git",
    "useIgnoreFile": true,
    "root": "../"
  }
}
```

If omitted, Biome uses the directory containing the current configuration file, falling back to the current working directory when no configuration directory is available. If neither directory is available, Biome disables VCS integration and emits a diagnostic.

### `vcs.defaultBranch`

**Type:** `string`

Sets the base branch used by `--changed` when `--since` is not provided. If neither `vcs.defaultBranch` nor `--since` is set, commands using `--changed` fail because Biome cannot determine the comparison base.

## `linter`

**Type:** `{ enabled?: boolean, includes?: string[], domains?: object, rules?: object }`

Configures linting and the rules Biome runs on selected files.

### `linter.enabled`

**Type:** `boolean`<br />
**Default:** `true`

Enables or disables the linter.

### `linter.includes`

**Type:** `string[]`

A list of [glob patterns](#glob-syntax-reference) selecting files to lint.

If omitted, all files selected by `files.includes` remain eligible for linting. An empty list (`[]`) selects no files.

:::note
This option can only narrow the files selected by `files.includes`.
:::

### `linter.domains`

**Type:** `Record<string, "recommended" | "all" | "none">`

Configures rules associated with a framework, library, project-wide analysis, or type analysis. Each key is a [domain name](/linter/domains/) and each value is one of:

- `"recommended"`: Enables the domain's recommended non-nursery rules.
- `"all"`: Enables all rules in the domain.
- `"none"`: Disables the domain.

Enabling the `project` or `types` domain causes Biome to scan project dependencies. The `types` domain additionally enables type-aware resolution.

### `linter.rules.recommended`

**Type:** `boolean`<br />
**Default:** `true`

Enables Biome's recommended non-nursery rules.

:::caution[Deprecated]
This option is deprecated and will be removed in the next major version. Use [`linter.rules.preset`](#linterrulespreset) instead, or run `biome migrate` to update the configuration.
:::

### `linter.rules.preset`

**Type:** `"recommended" | "all" | "none"`<br />
**Default:** `"recommended"`

Selects the baseline set of lint rules:

- `"recommended"`: Enables Biome's recommended non-nursery rules.
- `"all"`: Enables all non-nursery rules.
- `"none"`: Starts with no rules enabled.

Group-level settings and explicit rule settings override this preset. An explicit rule can therefore be enabled when the preset is `"none"`.

### `linter.rules.[group]`

**Type:** `"off" | "on" | "info" | "warn" | "error" | { preset?: "recommended" | "all" | "none", recommended?: boolean, [rule]?: "off" | "on" | "info" | "warn" | "error" | object }`

Configures all rules in one lint group:

- `a11y`: Detects accessibility problems.
- `complexity`: Detects unnecessarily complex code.
- `correctness`: Detects code that is incorrect or has no useful effect.
- `nursery`: Contains unstable rules that require explicit opt-in.
- `performance`: Detects code that may be less efficient than an available alternative.
- `security`: Detects potential security vulnerabilities.
- `style`: Enforces consistent and idiomatic code.
- `suspicious`: Detects code that is likely to be incorrect or unintended.

A group accepts either a string level or an object. A string applies one level to the group:

- `"off"`: Disables the group.
- `"on"`: Enables the group using each rule's default severity. Recommended rules default to error severity, while other rules default to warning severity.
- `"info"`: Enables the group with [information severity](/reference/diagnostics#information).
- `"warn"`: Enables the group with [warning severity](/reference/diagnostics#warning).
- `"error"`: Enables the group with [error severity](/reference/diagnostics#error).

```json title="biome.json"
{
  "linter": {
    "rules": {
      "a11y": "info"
    }
  }
}
```

### `linter.rules.[group].preset`

**Type:** `"recommended" | "all" | "none"`

Selects the baseline set of lint rules for one non-nursery group:

- `"recommended"`: Enables the group's recommended rules.
- `"all"`: Enables all rules in the group.
- `"none"`: Starts with no rules enabled in the group.

Explicit rule settings override this group preset, which in turn overrides `linter.rules.preset` for the group.

### `linter.rules.[group].recommended`

**Type:** `boolean`

Enables or disables the recommended rules in a non-nursery group.

The group's `preset` setting takes precedence when both options are set.

### `linter.rules.[group].[rule]`

**Type:** `"off" | "on" | "info" | "warn" | "error" | { level: "off" | "on" | "info" | "warn" | "error", options?: object, fix?: "none" | "safe" | "unsafe" }`

Configures an individual lint rule.

A rule accepts either a string level or an object. A string applies one level to the rule:

- `"off"`: Disables the rule.
- `"on"`: Enables the rule using its default severity. Recommended rules default to error severity, while other rules default to warning severity.
- `"info"`: Enables the rule with [information severity](/reference/diagnostics#information).
- `"warn"`: Enables the rule with [warning severity](/reference/diagnostics#warning).
- `"error"`: Enables the rule with [error severity](/reference/diagnostics#error).

An explicit rule configuration takes precedence over group-level settings and presets.

Depending on the rule, an object can contain the required `level` property and the optional `options` and `fix` properties:

```json title="biome.json"
{
  "linter": {
    "rules": {
      "complexity": {
        "noExcessiveCognitiveComplexity": {
          "level": "warn",
          "options": {
            "maxAllowedComplexity": 15
          }
        }
      }
    }
  }
}
```

:::tip
Run `biome explain <RULE>` to inspect its documentation and default severity.
:::

### `linter.rules.[group].[rule].fix`

**Type:** `"none" | "safe" | "unsafe"`

Overrides how Biome classifies or emits a rule's code fix. Only rules with a configurable fix accept this property:

- `"none"`: Prevents the rule from emitting a code fix.
- `"safe"`: Marks the fix as safe. Biome can apply it when writing files.
- `"unsafe"`: Marks the fix as unsafe. Biome applies it only when unsafe fixes are explicitly enabled.

Changing a fix's classification does not change the fix itself. Review a fix before marking it as safe. See [Configure the code fix](/linter/#configure-the-code-fix) for an example and details about safe and unsafe fixes.

This property is also available for rule configurations inside [`overrides`](#overrides).

## `assist`

**Type:** `{ enabled?: boolean, includes?: string[], actions?: object }`

Configures assist actions that Biome checks or applies on selected files.

### `assist.enabled`

**Type:** `boolean`<br />
**Default:** `true`

Enables or disables configured assist actions in the CLI and editor integrations.

### `assist.includes`

**Type:** `string[]`

A list of [glob patterns](#glob-syntax-reference) selecting files on which assist actions can run.

If omitted, all files selected by `files.includes` remain eligible for assist actions. An empty list (`[]`) selects no files.

:::note
This option can only narrow the files selected by `files.includes`.
:::

### `assist.actions.recommended`

**Type:** `boolean`<br />
**Default:** `true`

Enables Biome's recommended assist actions across all action groups.

### `assist.actions.preset`

**Type:** `"recommended" | "all" | "none"`<br />
**Default:** `"recommended"`

Selects the baseline set of assist actions:

- `"recommended"`: Enables Biome's recommended actions.
- `"all"`: Enables all actions.
- `"none"`: Starts with no actions enabled.

Group presets and explicit action settings override this preset. An explicit action can therefore be enabled when the preset is `"none"`.

### `assist.actions.[group]`

**Type:** `{ preset?: "recommended" | "all" | "none", recommended?: boolean, [action]?: "on" | "off" | object }`

Configures one group of assist actions:

- `source`: Contains source-level actions such as organizing imports and sorting supported declarations. These actions can be exposed as editor source actions and checked or applied by the CLI.

### `assist.actions.[group].preset`

**Type:** `"recommended" | "all" | "none"`

Selects the baseline set of assist actions for one group:

- `"recommended"`: Enables the group's recommended actions.
- `"all"`: Enables all actions in the group.
- `"none"`: Starts with no actions enabled in the group.

Explicit action settings override this group preset, which in turn overrides `assist.actions.preset` for the group.

### `assist.actions.[group].recommended`

**Type:** `boolean`

Enables or disables the recommended actions in one group.

The group's `preset` setting takes precedence when both options are set.

### `assist.actions.[group].[action]`

**Type:** `"on" | "off" | { level: "on" | "off", options: object }`

Configures an individual assist action.

An action accepts either a string level or an object. A string applies one level to the action:

- `"on"`: Enables the action.
- `"off"`: Disables the action.

An explicit action configuration takes precedence over group-level settings and presets.

An object contains the required `level` and `options` properties. The available options depend on the action:

```json title="biome.json"
{
  "assist": {
    "actions": {
      "source": {
        "useSortedKeys": {
          "level": "on",
          "options": {
            "sortOrder": "natural"
          }
        }
      }
    }
  }
}
```

See the [assist documentation](/assist/) for the options supported by each action.

## `formatter`

**Type:** `{ enabled?: boolean, includes?: string[], formatWithErrors?: boolean, indentStyle?: "tab" | "space", indentWidth?: integer, lineEnding?: "lf" | "crlf" | "cr" | "auto", lineWidth?: integer, attributePosition?: "auto" | "multiline", bracketSameLine?: boolean, bracketSpacing?: boolean, delimiterSpacing?: boolean, expand?: "auto" | "always" | "never", trailingNewline?: boolean, useEditorconfig?: boolean }`

Configures formatting for selected files.

### `formatter.enabled`

**Type:** `boolean`<br />
**Default:** `true`

Enables or disables the formatter.

### `formatter.includes`

**Type:** `string[]`

A list of [glob patterns](#glob-syntax-reference) selecting files to format.

If omitted, all files selected by `files.includes` remain eligible for formatting. An empty list (`[]`) selects no files.

:::note
This option can only narrow the files selected by `files.includes`.
:::

### `formatter.formatWithErrors`

**Type:** `boolean`<br />
**Default:** `false`

Controls whether Biome formats files that contain syntax errors.

### `formatter.indentStyle`

**Type:** `"tab" | "space"`<br />
**Default:** `"tab"`

Selects the indentation style:

- `"tab"`: Uses tabs for indentation.
- `"space"`: Uses spaces for indentation.

### `formatter.indentWidth`

**Type:** `integer`<br />
**Default:** `2`

Sets the indentation width. With `"space"` indentation, this is the number of spaces emitted per indentation level. With `"tab"` indentation, Biome emits one tab per level and uses this value as the tab's display width when calculating line length.

Accepted values range from `0` through `24`.

### `formatter.lineEnding`

**Type:** `"lf" | "crlf" | "cr" | "auto"`<br />
**Default:** `"lf"`

Selects the line-ending sequence:

- `"lf"`: Line Feed (`\n`), commonly used on Linux and macOS.
- `"crlf"`: Carriage Return followed by Line Feed (`\r\n`), commonly used on Windows.
- `"cr"`: Carriage Return (`\r`), which is rarely used.
- `"auto"`: Uses CRLF on Windows and LF on other platforms.

### `formatter.lineWidth`

**Type:** `integer`<br />
**Default:** `80`

Sets the preferred maximum line width used when deciding where to wrap code. Some content, such as long unbreakable strings, may still exceed this width.

Accepted values range from `1` through `320`.

### `formatter.attributePosition`

**Type:** `"auto" | "multiline"`<br />
**Default:** `"auto"`

Controls attribute placement in HTML-like languages:

- `"auto"`: Places attributes automatically and wraps them when needed.
- `"multiline"`: Places each attribute on its own line when an element has multiple attributes.

### `formatter.bracketSameLine`

**Type:** `boolean`<br />
**Default:** `false`

Controls the placement of the closing bracket for multiline HTML and JSX opening tags.

Biome places the bracket at the end of the last attribute line when enabled and on its own line after the last attribute when disabled.

This option also affects self-closing HTML elements, but self-closing JSX elements are unaffected.

### `formatter.bracketSpacing`

**Type:** `boolean`<br />
**Default:** `true`

Controls spaces inside braces in supported single-line structures. The affected structures vary by language.

### `formatter.delimiterSpacing`

**Type:** `boolean`<br />
**Default:** `false`

Controls spaces immediately inside supported delimiters when their content fits on one line.

Biome does not add spaces before opening delimiters or inside empty delimiters. The affected delimiters vary by language.

### `formatter.expand`

**Type:** `"auto" | "always" | "never"`<br />
**Default:** `"auto"`

Controls whether arrays and objects are formatted on one line or multiple lines:

- `"auto"`: Formats objects on multiple lines if the first property has a leading newline, and keeps arrays on one line when they fit.
- `"always"`: Formats arrays and objects on multiple lines.
- `"never"`: Keeps arrays and objects on one line when they fit.

When formatting `package.json`, Biome uses `"always"` unless expansion is configured explicitly.

### `formatter.trailingNewline`

**Type:** `boolean`<br />
**Default:** `true`

Controls whether formatted files end with a newline.

:::caution[Keep trailing newlines enabled]
Setting this option to `false` is strongly discouraged. Files without a final newline can cause [compatibility issues](https://thoughtbot.com/blog/no-newline-at-end-of-file) with [text-processing tools](https://unix.stackexchange.com/questions/345548/how-to-cat-files-together-adding-missing-newlines-at-end-of-some-files) and produce [confusing version-control output](https://callmeryan.medium.com/no-newline-at-end-of-file-navigating-gits-warning-for-android-developers-af14e73dd804).
:::

### `formatter.useEditorconfig`

**Type:** `boolean`<br />
**Default:** `false`

Controls whether Biome loads formatter settings from an `.editorconfig` file. Biome currently reads `indent_style`, `indent_size`, `end_of_line`, and `insert_final_newline`. Settings in `biome.json` or `biome.jsonc` take precedence.

Biome loads only one `.editorconfig`. Nested cascading configurations and the EditorConfig `root` property are not currently supported.

## `overrides`

**Type:** `{ includes?: string[], formatter?: object, linter?: object, assist?: object, files?: object, plugins?: (string | object)[], javascript?: object, json?: object, css?: object, graphql?: object, grit?: object, html?: object }[]`

Configures settings for files selected by each override.

When multiple overrides configure the same single-value setting, the last matching override takes precedence.

### `overrides.<ITEM>.includes`

**Type:** `string[]`

A list of [glob patterns](#glob-syntax-reference) selecting the files to which the override applies.

If omitted, the override applies to every file. An empty list (`[]`) applies to no files.

For example, this override changes the line width for JavaScript files directly under `scripts`:

```jsonc title="biome.jsonc"
{
  "overrides": [
    {
      "includes": ["scripts/*.js"],
      // Settings in this object apply only to matched files.
      "formatter": {
        "lineWidth": 100
      }
    }
  ]
}
```

### `overrides.<ITEM>.formatter`

**Type:** `{ enabled?: boolean, formatWithErrors?: boolean, indentStyle?: "tab" | "space", indentSize?: integer, indentWidth?: integer, lineEnding?: "lf" | "crlf" | "cr" | "auto", lineWidth?: integer, attributePosition?: "auto" | "multiline", bracketSameLine?: boolean, bracketSpacing?: boolean, delimiterSpacing?: boolean, expand?: "auto" | "always" | "never", trailingCommas?: "all" | "es5" | "none", trailingNewline?: boolean }`

Configures formatter settings for files selected by this override.

### `overrides.<ITEM>.linter`

**Type:** `{ enabled?: boolean, domains?: object, rules?: object }`

Configures linter settings for files selected by this override.

```json title="biome.json"
{
  "overrides": [
    {
      "includes": ["lib/**"],
      "linter": {
        "rules": {
          "suspicious": {
            "noDebugger": "off"
          }
        }
      }
    },
    {
      "includes": ["shims/**"],
      "linter": {
        "enabled": false
      }
    }
  ]
}
```

### `overrides.<ITEM>.assist`

**Type:** `{ enabled?: boolean, actions?: object }`

Configures assist settings for files selected by this override.

### `overrides.<ITEM>.files`

**Type:** `{ maxSize?: integer }`

Configures file-handling settings for files selected by this override.

### `overrides.<ITEM>.plugins`

**Type:** `(string | { path: string, includes?: string[] })[]`

Adds plugins for files selected by this override. They run in addition to top-level plugins.

### `overrides.<ITEM>.javascript`

**Type:** `{ parser?: object, formatter?: object, linter?: object, assist?: object, resolver?: object, globals?: string[], jsxRuntime?: "transparent" | "reactClassic", experimentalEmbeddedSnippetsEnabled?: boolean }`

Configures JavaScript-specific settings for files selected by this override.

```json title="biome.json"
{
  "javascript": {
    "formatter": {
      "quoteStyle": "single"
    }
  },
  "overrides": [
    {
      "includes": ["lib/**"],
      "javascript": {
        "formatter": {
          "quoteStyle": "double"
        }
      }
    }
  ]
}
```

### `overrides.<ITEM>.json`

**Type:** `{ parser?: object, formatter?: object, linter?: object, assist?: object }`

Configures JSON-specific settings for files selected by this override.

The following override enables comments and trailing commas in JSON files below `.vscode/`:

```json title="biome.json"
{
  "overrides": [
    {
      "includes": [".vscode/**"],
      "json": {
        "parser": {
          "allowComments": true,
          "allowTrailingCommas": true
        }
      }
    }
  ]
}
```

### `overrides.<ITEM>.css`

**Type:** `{ parser?: object, formatter?: object, globals?: string[], linter?: object, assist?: object }`

Configures CSS-specific settings for files selected by this override.

### `overrides.<ITEM>.graphql`

**Type:** `{ formatter?: object, linter?: object, assist?: object }`

Configures GraphQL-specific settings for files selected by this override.

### `overrides.<ITEM>.grit`

**Type:** `{ formatter?: object, linter?: object, assist?: object }`

Configures GritQL-specific settings for files selected by this override.

### `overrides.<ITEM>.html`

**Type:** `{ experimentalFullSupportEnabled?: boolean, parser?: object, formatter?: object, linter?: object, assist?: object }`

Configures HTML-specific settings for files selected by this override.

## Language-specific options

The following sections describe parser, formatter, linter, and assist options for individual languages.

:::note
Language-specific settings take precedence over corresponding global settings.

Global settings apply when their language-specific counterparts are omitted, unless stated otherwise.
:::

## `javascript`

**Type:** `{ parser?: object, formatter?: object, linter?: object, assist?: object, resolver?: object, globals?: string[], jsxRuntime?: "transparent" | "reactClassic", experimentalEmbeddedSnippetsEnabled?: boolean }`

Options applied to JavaScript, TypeScript, JSX, TSX, and supported languages that embed JavaScript.

### `javascript.parser.unsafeParameterDecoratorsEnabled`

**Type:** `boolean`<br />
**Default:** `false`

Enables parsing decorators on class parameters, such as `method(@Decorator() value)`. This syntax belongs to an old experimental proposal and may change, so enable it only when existing code requires it.

### `javascript.parser.gritMetavariables`

**Type:** `boolean`<br />
**Default:** `false`

Enables parsing Grit metavariables in JavaScript and TypeScript syntax.

### `javascript.parser.jsxEverywhere`

**Type:** `boolean`<br />
**Default:** `true`

## Glob syntax reference

Biome uses glob patterns to match file and directory paths relative to the configuration directory. Patterns are case-sensitive and use `/` as the path separator.

| Syntax | Meaning | Example |
| --- | --- | --- |
| `*` | Matches characters within one path segment | `src/*.js` |
| `**` | Matches zero or more complete path segments | `**/*.js` |
| `{a,b}` | Matches either alternative | `**/*.{js,ts}` |
| `\` | Escapes a special character so it is matched literally. Write `\\` in JSON configuration files. | `file\\?.js` |
| `!pattern` | Excludes matching paths | `!**/*.test.js` |
| `!!pattern` | Force-ignores matching paths in `files.includes` | `!!**/dist` |

Patterns are evaluated in order, and the last matching pattern wins. For example, the following patterns include JavaScript files, exclude test files, then include `src/special.test.js` again:

```json
["**/*.js", "!**/*.test.js", "src/special.test.js"]
```

:::tip
Start with a positive pattern because a list containing only exclusions selects no files.
:::

`files.includes` applies to both files and directories, while other `includes` settings filter files for a specific feature. This changes how directory exclusions are written:

| Goal | `files.includes` | Other `includes` settings |
| --- | --- | --- |
| Exclude the root `dist` directory | `!dist` | `!dist/**` |
| Exclude `dist` directories at any depth | `!**/dist` | `!**/dist/**` |
| Force-ignore `dist` directories at any depth | `!!**/dist` | Not supported |

The `!!` prefix creates a force-ignore pattern only in `files.includes`. In other `includes` settings, it behaves like a regular `!` exclusion. See [scanner behavior](#scanner-behavior) for details.

Biome intentionally has a limited glob syntax, with a few expected features not supported:

| Syntax | Behavior |
| --- | --- |
| `?` | Not supported as a wildcard |
| `[abc]` and `[0-9]` | Character classes are not supported |
| `{{a,b},c}` | Nested alternatives are not supported |
| `a**`, `**a`, and `***` | `**` must occupy an entire path segment |
| `**/**` | Consecutive globstars are not supported |

:::caution[CLI globs depend on your shell]
Biome does not interpret CLI arguments as globs. Unquoted globs may still work because your shell expands them into file paths before Biome runs.

Shell support varies, so prefer an `includes` configuration for glob-based selection.
:::
