Biome can automatically migrate your existing ESLint and Prettier configuration files to the equivalent `biome.json` file. Run one or more commands according to your project:

```shell
biome migrate eslint --write
biome migrate prettier --write
biome migrate stylelint --write
```

To understand what changes when you switch tools, see [Comparison with other tools](/introduction/comparison-with-other-tools).

## Migrate from ESLint

`biome migrate eslint` ports the rules, globals, overrides, and ignore patterns from your ESLint configuration. It reads both legacy and flat configuration files, follows `extends`, loads shared and plugin configurations, and migrates `.eslintignore`.

Given the following ESLint configuration:

```json title=".eslintrc.json"
{
  "globals": {
    "Global1": "readonly"
  },
  "rules": {
    "eqeqeq": "error",
    "no-var": "error"
  },
  "overrides": [
    {
      "files": ["tests/**"],
      "rules": {
        "eqeqeq": "off"
      }
    }
  ]
}
```

Run the following command to migrate it:

<PackageManagerBiomeCommand command="migrate eslint --write" />

The command produces the following `biome.json`:

<Code title="biome.json" lang="json" code={`{
	"$schema": "https://biomejs.dev/schemas/${version}/schema.json",
	"vcs": { "enabled": false, "clientKind": "git", "useIgnoreFile": false },
	"files": { "ignoreUnknown": false },
	"formatter": { "enabled": true, "indentStyle": "tab" },
	"linter": {
		"enabled": true,
		"rules": {
			"preset": "none",
			"suspicious": { "noDoubleEquals": "error", "noVar": "error" }
		}
	},
	"javascript": {
		"formatter": { "quoteStyle": "double" },
		"globals": ["Global1"]
	},
	"overrides": [
		{
			"includes": ["tests/**"],
			"linter": { "rules": { "suspicious": { "noDoubleEquals": "off" } } }
		}
	],
	"assist": {
		"enabled": true,
		"actions": { "source": { "organizeImports": "on" } }
	}
}`} />

The command replaces the linter settings in your existing `biome.json`. It sets the rule preset to `none` and enables only the rules it migrated. Review the result before relying on it.

### Inspired rules

Each Biome rule is either identical to its ESLint source or only inspired by it, as listed on the [Rule sources](/linter/rules-sources) page. By default, the command migrates identical rules only. Pass the `--include-inspired` flag to migrate inspired rules as well:

<PackageManagerBiomeCommand command="migrate eslint --write --include-inspired" />

Even with inspired rules, the result does not behave exactly like ESLint, because some rule options are not implemented and some rules deliberately differ. See [Rules and compatibility](/introduction/comparison-with-other-tools#rules-and-compatibility) for the differences.

### Cyclic references

Some plugins and shared configurations export objects with cyclic references, which Biome cannot load. If the migration fails with such an error, comment out the plugins and shared configurations, run the migration, then restore them one at a time to find the one responsible:

```js title="eslint.config.js" del={8,9,12,13} ins={10,11,14,15}
import { defineConfig } from 'eslint';
import jsxA11y from 'eslint-plugin-jsx-a11y';
import react from '@eslint-react/eslint-plugin';
import stylistic from '@stylistic/eslint-plugin';
import tsEslint from 'typescript-eslint';

export default defineConfig([
  react.configs.recommended,
  jsxA11y.flatConfigs.recommended,
  // react.configs.recommended,
  // jsxA11y.flatConfigs.recommended,
  {
    plugins: {
      '@stylistic': stylistic,
      '@typescript-eslint': tsEslint.plugin,
      // '@stylistic': stylistic,
      // '@typescript-eslint': tsEslint.plugin,
    },
  }
]);
```

Once the migration is done, configure the rules from those plugins by hand in `biome.json`.

## Migrate from Prettier

`biome migrate prettier` ports the options from your Prettier configuration and the patterns from `.prettierignore`.

Biome's formatter defaults differ from Prettier's, so the command writes every option explicitly to keep your current output. See [Output and compatibility](/introduction/comparison-with-other-tools#output-and-compatibility) for the differences that remain.

Given the following Prettier configuration:

```json title=".prettierrc.json"
{
	"useTabs": false,
	"singleQuote": true,
	"overrides": [
		{
			"files": ["*.json"],
			"options": { "tabWidth": 2 }
		}
	]
}
```

Run the following command to migrate it:

<PackageManagerBiomeCommand command="migrate prettier --write" />

The command produces the following `biome.json`:

## Migrate from Stylelint

Biome can lint and format CSS files.
Many of Biome's CSS linter rules are inspired by or identical to the [Stylelint](https://stylelint.io/) rules.
However, Biome has its own naming convention for its rules.
Biome uses `camelCaseRuleName` while Stylelint uses `kebab-case-rule-name`.
Moreover, Biome has often chosen to use different names to better convey the intent of its rules.
The source of a rule can be found on the page describing the rule.
You can also find the equivalent Biome rule from a Stylelint rule using the [dedicated page](/linter/rules-sources).

To ease the migration, Biome provides the `biome migrate stylelint` subcommand.
This subcommand will read your Stylelint configuration and attempt to port its settings to Biome.
It supports the `extends` field and loads both shared and plugin configurations.
The subcommand needs Node.js to load and resolve all the plugins and `extends` configured in the Stylelint configuration file.
The subcommand also migrates the `ignoreFiles` field.

Given the following Stylelint configuration:

```json title=".stylelintrc.json"
{
  "extends": ["stylelint-config-recommended"],
  "ignoreFiles": ["dist/**"],
  "rules": {
    "block-no-empty": true,
    "font-family-no-duplicate-names": true,
    "keyframe-declaration-no-important": true
  },
  "overrides": [
    {
      "files": ["*.scss"],
      "rules": {
        "block-no-empty": null
      }
    }
  ]
}
```

And the following Biome configuration:

```json title="biome.json"
{
	"linter": {
		"enabled": true,
		"rules": {
			"recommended": true
		}
	}
}
```

Run the following command to migrate your Stylelint configuration to Biome.

<PackageManagerBiomeCommand command="migrate stylelint --write"/>

The subcommand overwrites your initial Biome configuration.
For example, it disables `recommended`.
This results in the following Biome configuration:

```json title="biome.json"
{
	"organizeImports": { "enabled": true },
	"linter": {
		"enabled": true,
		"rules": {
			"recommended": false,
			"suspicious": {
				"noDuplicateFontNames": "error",
				"noEmptyBlock": "error",
				"noImportantInKeyframe": "error"
			}
		}
	},
	"overrides": [
		{
			"include": ["*.scss"],
			"linter": {
        "rules": {
          "suspicious": {
            "noEmptyBlock": "off"
          }
        }
      }
		}
	]
}
```

For now, `biome migrate stylelint` only supports the JSON (`.stylelintrc.json`) and JavaScript (`.stylelintrc.js`, `.stylelintrc.cjs`, `.stylelintrc.mjs`) configuration formats.
Configuration written in YAML is not supported.

By default, Biome doesn't migrate inspired rules.
You can use the CLI flag `--include-inspired` to migrate them.

<PackageManagerBiomeCommand command="migrate stylelint --write --include-inspired"/>

Note that you are unlikely to get exactly the same behavior as Stylelint because Biome has chosen not to implement some rule options or to deviate slightly from the original implementation.

Since Stylelint takes VCS ignore files into account,
we recommend that you enable Biome's [VCS integration](/guides/integrate-in-vcs).

## After migrating

ESLint and Prettier skip the files in your `.gitignore` by default. Biome does so only when its VCS integration is enabled, so [enable it](/configuration/integrate-with-vcs) to keep the same set of files ignored.

Once you are satisfied with the result, remove ESLint, Prettier, and their plugins from your dependencies, and replace their [editor extensions](/configuration/editors) with Biome's.
